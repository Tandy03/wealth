# Fino — трекер інвестицій і особистих фінансів

Fino має вебверсію з локальним Node.js backend та Android-застосунок на Capacitor. Вебверсія зберігає портфель у JSON-файлі; Android працює з власною локальною копією та Google Drive.

## Можливості

**Portfolio Share Card:** у Dashboard кнопка Share відкриває локальний preview з періодами, приватністю й чотирма темами; вебверсія зберігає PNG 1080 × 1080 та використовує Web Share там, де він підтримує файли. Для Android у коді підготовлений окремий `PortfolioShare` plugin: системне збереження PNG і Share Sheet, без змін JSON-перенесення. Старий APK без плагіна підтримує лише preview. Android-збірка й перевірка на телефоні ще не виконувалися. Методика: [PORTFOLIO-SHARE.md](PORTFOLIO-SHARE.md); native-контракт і перевірки: [ANDROID-PNG-SHARE.md](ANDROID-PNG-SHARE.md).

- Портфель: ОВДП, REIT, акції, ETF, заощадження, депозити, NovaPay і Crypto Earn.
- Додавання, редагування, докупівля, продаж, видалення та об’єднання однакових активів.
- Історія операцій і цін, календар купонів, дивідендів, погашень та нотаток.
- Натискання активу в Dashboard або Portfolio відкриває спільну сторінку всіх його покупок з оглядом, операціями, виплатами, історією ціни/вартості та умовами. Групування збігається з Portfolio: тип і назва активу. Залишок, собівартість та результати підсумовуються; історія закритих частин зберігається. Первинні записи не об’єднуються і не переписуються. Сторінка використовує завантажений портфель і локальні ресурси, зокрема в Android offline.
- Dashboard окремо показує нереалізований результат відкритих позицій із відомими котируваннями та реалізований результат: зафіксований прибуток продажів + отриманий інвестиційний дохід. Заплановані виплати й повернена основна сума не є прибутком. Валюта підсумків — UAH, при наведенні/фокусі — USD. За недоступності НБУ резервні курси становлять USD = 45 UAH та EUR = 51 UAH. Return при наведенні/фокусі порівнюється із S&P 500 за період інвестування; вже відкрита картка оновлюється після надходження історії.
- Захист нових фінансових команд від повтору після втраченої відповіді: `operationId`, атомарні квитанції й 409 при конфліктному повторі; [IDEMPOTENCY.md](IDEMPOTENCY.md).
- Позначення отриманих виплат і закриття активу після погашення.
- Dashboard із поточною вартістю активів у картці Portfolio, прибуток, XIRR, структура портфеля, історична дохідність і калькулятор ребалансування.
- Аналітика прибутку відділяє реалізований результат за датами від поточної переоцінки; XIRR враховує статуси та показує повноту котирувань/курсів. Dashboard має сценарії додаткового капіталу, Analytics — концентрацію позицій, емітентів, інструментів, секторів і валют. Методика й обмеження: [ANALYTICS.md](ANALYTICS.md).
- Картка $1 000/місяць використовує отримані регулярні дивіденди/купони за останні 365 днів і середню денну собівартість відкритих позицій. Виплати й денний капітал переводяться за історичними курсами; поточна база й ціль — за курсом розрахунку. Видно отримання, базу, річну дохідність, необхідний/додатковий капітал, сценарії та FX. Коротка історія й оцінні курси позначені; неповні дані приховують сценарні суми. Погашення, продажі, переоцінка та savings виключені.
- Portfolio Rebalance: два графіки розподілу, редактор часток зі слайдерами, явна нормалізація до 100% і таблиця докупівель. Формули чинного алгоритму збережено; деталі й перевірки — у [REBALANCE-UI.md](REBALANCE-UI.md). Частки, заплановані активи й виключені рядки зберігаються після оновлення сторінки та синхронізуються через Drive між оновленими клієнтами; помилки збереження й конфлікти показуються явно.
- Особистий бюджет: витрати, категорії, місячний архів, графіки й кредити.
- Перед заміною локального чи хмарного портфеля показується порівняння версій із датами, пристроями та відмінностями; застарілий вибір потребує повторного перегляду. [Політика Android backup](ANDROID-BACKUP.md) відокремлює системний backup від резервних копій Fino у Drive.
- На телефоні бюджет використовує таблицю з горизонтальним прокручуванням і тими самими полями та сценарієм збереження, що й desktop. Область таблиці доступна через Tab, має локалізовану назву й видимий фокус; перша колонка з категоріями залишається на місці під час прокручування. Dashboard показує чотири головні показники у два стовпці; інші показники й пояснення розкриваються за потреби. Навігація Investment має підказку гортання й видиму смугу прокручування.
- Ринкові графіки, валютна історія, макроекономічні показники.
- Теми, налаштування шрифту та мови; PIN і біометричне розблокування Android.
- Синхронізація з Google Drive; desktop backend також створює резервні копії.

## Вимоги

- Node.js **22.13+ у гілці 22 або 24+** і npm; ці версії сумісні з Capacitor CLI та тестовим середовищем jsdom.
- Для Android: JDK 21, Android SDK із платформою API 36; Android Studio зручна для налаштування SDK і запуску на пристрої.
- Мінімальна версія Android: 7.0 / API 24.

## Запуск вебверсії

Frontend використовує ES modules і Vite: `npm.cmd run dev` запускає Express + Vite на одному origin; `npm.cmd start` спочатку збирає frontend і віддає production-ресурси. Окрема збірка: `npm.cmd run build:frontend`. Архітектура, команди, UI-тести та порівняння завантаження — у [FRONTEND-MODULES.md](FRONTEND-MODULES.md).

З кореня проєкту:

~~~powershell
npm.cmd install
Copy-Item .env.example .env
npm.cmd run dev
~~~

Копіюйте приклад лише якщо власного .env ще немає. Відкрийте **http://localhost:3000**. Для запуску без автоматичного перезапуску використовуйте `npm.cmd start`. Порт можна змінити змінною PORT. Сервер слухає лише `127.0.0.1`; зайнятий порт завершує запуск із помилкою. У PowerShell команди `npm.cmd` працюють і з політикою заборони `.ps1`-скриптів; в інших оболонках можна використовувати `npm`.

Локальне ведення портфеля не потребує API-ключів. Доступність ринкових даних і синхронізації залежить від відповідних налаштувань та мережі.

~~~text

  app.js                    # Middleware, складання сервісів і підключення маршрутизаторів
  routes/
    assets.js               # Активи, докупівля, об’єднання, оновлення цін
    sales.js                # Продажі
    payments.js             # Виплати та позначення отримання
    calendar.js             # Нотатки календаря
    wallet.js               # Особистий бюджет
    market.js               # Ринкові й макроекономічні дані
    transactions.js         # Історія операцій
    data.js                 # Повний документ даних
    sync.js                 # Google Drive і сумісні адреси API
  domain/
    assetService.js         # Читання, створення, редагування й видалення активу
    purchaseService.js      # Докупівля й запис додаткового BUY
    saleService.js          # Продажі, собівартість і результат
    assetMergeService.js    # Сумісність і об’єднання позицій
    mutation.js             # Єдиний application-level вхід у repository queue
    assetSyncService.js     # Завантаження котирувань перед коротким застосуванням змін
    paymentService.js       # Отримання виплат і закриття позицій
    state.js                # Нормалізація та перерахунок після читання
    portfolio.js            # Кількості, виплати, історія цін і сумісність старих даних
  services/
    syncService.js          # Google Drive
    market/request.js       # Тайм-аут заголовків і JSON-відповіді провайдера
    binance/                # Зовнішні інтеграції
    twelveData/
    nbu/
    frankfurter/
    fred/
    macroeconomics/
    googleDrive/
  data/
    repository.js           # Читання JSON, атомарний запис, ревізії, черга змін
    data.json               # Локальні фінансові дані; не входить до Git
  validators/               # Валідація дат, кількостей і базових полів активів
  utils/                    # Числа, валюти, ID та очікувані помилки операцій
  config/                   # Завантаження .env і локальні Google OAuth-файли
  scripts/                  # Google-авторизація й генерація Android-конфігурації
  tests/                    # Модульні й HTTP-регресійні тести
frontend/                   # HTML, CSS, JavaScript і зображення
shared/                     # Спільна модель, валідація, фінансові правила й помилки
  js/state-store.js          # Єдина публікація фінансових змін і збереження wallet/rebalance
  js/portfolio-rules.js      # Compatibility export до shared/portfolio-rules
  js/validation.js           # Compatibility export до shared/validation
  js/request.js              # Compatibility export до shared/request
~~~

Потік запиту: **route → service → repository / зовнішня інтеграція**. Маршрути відповідають за HTTP-параметри, коди й JSON-відповіді. Сервіси виконують операції та фінансові розрахунки. Фінансові зміни проходять через чергу repository. Зовнішні запити Drive виконуються окремо; завантаження бере чергу лише для перевірки актуальності й локального застосування копії.

У frontend фінансовий документ змінюють тільки store-команди; читання/аналітика не нормалізують і не доповнюють опубліковані дані. Контракти команд, результат збереження, захист від застарілих відповідей і правило read-only для UI описані в [FRONTEND-STATE.md](FRONTEND-STATE.md).

Bootstrap отримує залежності явно. Перелік дозволених browser globals, їхні власники й порядок локальних скриптів закріплені в `frontend-globals.json` і перевіряються тестами та mobile preflight. `FinoOutbox` і recovery controller мають явних власників; outbox зберігає невідомі команди до повтору після restart, ізоляцію origin/account і ручне відновлення без нових ID. Повний replay-result зберігається щонайменше 30 днів, потім компактується в tombstone; деталі — [IDEMPOTENCY.md](IDEMPOTENCY.md). Правила модулів і запуск реального HTML для web/native — [FRONTEND-MODULES.md](FRONTEND-MODULES.md).

`createApp({ repository })` дозволяє запускати API з ізольованим сховищем у тестах. Портфельні use cases розділені між asset/purchase/sale/merge services; старий агрегатор вилучено. Доменні команди входять у `repository.runMutation()` через `domain/mutation.js` рівно один раз; routes не беруть чергу. Контракти, залежності й правила атомарності — у [PORTFOLIO-SERVICES.md](PORTFOLIO-SERVICES.md). Синхронізація котирувань завантажує зовнішні дані до входу в чергу, потім читає свіжий стан і застосовує їх. Android так само застосовує котирування до актуальної копії й перевіряє, що акаунт та інструмент не змінилися під час очікування.

## API

Адреси й формати відповідей збережені після поділу backend на модулі.

| Група | Основні адреси |
| --- | --- |
| Дані | GET /api/data |
| Активи | GET/POST /api/assets, PUT/DELETE /api/assets/:id |
| Докупівля / об’єднання | POST /api/assets/:id/buy, POST /api/assets/merge |
| Оновлення цін | POST /api/assets/sync-inzhur |
| Продажі | GET/POST /api/sales |
| Операції | GET/POST /api/transactions |
| Виплати | GET/POST /api/payments, PATCH /api/payments/:id/received |
| Календар | GET/POST /api/calendar-notes |
| Бюджет | PUT /api/wallet; читання через GET /api/data |
| Ринок | GET /api/exchange-rates, /api/inzhur-assets, /api/market-data/* |
| Макроекономіка | GET /api/macroeconomics, /api/macroeconomics/policy-rate |
| Синхронізація | GET /api/sync/status, POST /api/sync/google-drive |

Локальна браузерна сесія поновлюється автоматично після перезапуску backend: клієнт використовує `POST /api/session`, що приймає лише запит застосунку зі спеціальним заголовком і проходить перевірку origin/Host. Запит збереження, відхилений до виконання через застарілу сесію, повторюється один раз. Це окремий механізм від Google-авторизації. Після оновлення коду вже відкриту вкладку слід один раз перезавантажити через `Ctrl+F5`.

Сумісні адреси /api/google-drive/status і /api/google-drive/sync також доступні. Редагування активу через PUT передбачає повний набір основних полів, а не довільний частковий patch.

API приймає JSON, відхиляє чужий `Origin`, міжсайтові запити та імена хостів поза localhost. Це локальний особистий застосунок; його API не має користувацьких облікових записів. Невідома API-адреса повертає JSON із 404. Валідація повертає 400, заборонений доступ — 403, неправильний Content-Type — 415, конфлікт Drive — 409, помилка локального сховища — 503, збій провайдера — 502, тайм-аут — 504. Поле відповіді `{ error }` і заголовки `X-Request-Id` / `X-Error-Category` доступні для діагностики.

## Фінансові правила

- `asset.quantity` — загальна придбана кількість; `remainingQuantity` — поточний залишок; `remainingCostBasis` — його собівартість. `purchasePrice` для активної позиції відображає середню ціну залишку. Докупівля додає свою вартість до собівартості непроданих одиниць. Приклад: 10 × 100, продаж 5, докупівля 5 × 200 → залишок 10, собівартість 1 500, середня ціна 150.
- Нові продажі використовують середню собівартість і зберігають `costBasisMethod: moving_average`. Результати попередніх продажів не перераховуються після докупівлі чи редагування поточної ціни. Історична аналітика використовує той самий спосіб списання для нових операцій; для старих записів без методу зберігається відновлення FIFO. Порядок операцій одного дня визначається журналом транзакцій.
- Єдина функція залишку на дату враховує покупки, продажі та фактичне закриття. Майбутні купони й погашення на одиницю перераховуються за цим залишком. Отримані виплати зберігаються; під час погашення також фіксується собівартість закритого залишку.
- Право на дивіденди за замовчуванням визначається на останній день попереднього місяця, як у попередній версії. Поле активу `dividendRecordRule` може бути `previous_month_end` або `payment_date`. У `POST /api/payments` для DIVIDEND можна задати конкретний `recordDate`, який не пізніший за дату виплати. Продаж після цієї дати не забирає вже визначене право на дивіденд.
- Об’єднання перевіряє тип, назву, валюту, інструмент, ISIN, ticker/symbol, погашення та умови виплат. Закриті або погашені позиції не об’єднуються. Майбутній графік перебудовується без дублів; отримані виплати залишаються окремими записами. Якщо частину дивіденду вже отримано, планується лише неоплачена частина.
- Створення й редагування використовують спільні правила: справжні календарні дати, скінченні невід’ємні числа, ставка 0–1000%, термін NovaPay 1–12 місяців, погашення після покупки, купони в межах строку. Після кількох покупок або продажів загальні поля початкової покупки не можна довільно переписувати через редактор активу; використовуйте окремі операції докупівлі й продажу. Для єдиної покупки редактор оновлює відповідний запис BUY.
- Збереження бюджету працює з чернеткою: стан змінюється після успішної відповіді API. Помилка повертає поле плану до збереженого значення, а форма витрати зберігає введені дані для повторної спроби. Текст із старих невідомих типів платежів екранується перед вставленням у HTML; нові платежі допускають тільки DIVIDEND, COUPON і MATURITY.

Старі документи з неповною історією залишаються читабельними. Якщо ціна початкової покупки відсутня, її собівартість відновлюється з доступної ціни активу й фіксується як `legacyPurchaseCost`, щоб повторний перерахунок не змінював результат. Під час об’єднання відсутні початкові покупки доповнюються явно позначеними записами `source: legacy`. Невідомі поля документа зберігаються.

НБУ та Inzhur мають обмеження очікування 10 секунд, включно з читанням JSON. Android обмежує очікування зовнішнього fetch та читання тіла відповіді. Завантаження ринкових даних не утримує чергу локальних фінансових змін.

Локальні дані відкриваються й зберігаються без очікування Drive. Веб запускає початкове підключення у фоні й оновлює екран після нього. У мобільному адаптері мережеві операції мають окрему чергу; швидкі послідовні зміни об’єднуються в один upload. Підтвердження старого upload не підтверджує новіші правки, а завантаження з Drive перевіряє, чи локальні дані не змінилися. Журнал Android версії 2 зберігає початкову копію та зміни, читає старий формат і перевіряє контрольні суми під час відновлення. Ці локальні правки від 17.10.2026 ще не включені до APK і не опубліковані на GitHub.

Для макроекономіки використовуються окремі межі: 25 секунд для НБУ/Держстату, 45 секунд для щоденної облікової ставки. ВВП завантажується через фільтри [офіційного SDMX API](https://stat.gov.ua/uk/development-api/sdmx-api-v3): лише потрібні ряди України, а не весь набір національних рахунків. Помилки джерел кешуються максимум 30 секунд; повторне відкриття розділу дозволяє поновити невдалий графік. Тести запускаються максимум у чотирьох процесах одночасно, щоб перевірка запуску сервера не залежала від перевантаження комп’ютера.

НБУ, Inzhur і Frankfurter використовуються без ключів. Деякі макроекономічні дані завантажуються з офіційних джерел України.

### Google Drive у вебверсії

1. Налаштуйте Google OAuth client із доступом до Drive API та збережіть credentials у backend/config/google-credentials.json.
2. Виконайте npm run google-auth і пройдіть авторизацію. Використовується scope drive.file.
3. У .env задайте GOOGLE_DRIVE_SYNC_ENABLED=true та за потреби ID файлу.
4. Перезапустіть backend.

Основний файл за замовчуванням — fino-data.json; резервні копії desktop backend зберігає в fino-backups, автоматичні копії мають окремий ліміт 10/30 днів, ручні — 30/90 днів. Видаляються лише власні позначені копії; старі й сторонні файли не зачіпаються. За помилки початкової синхронізації backend використовує локальну копію. Статус і ручні дії доступні через інтерфейс налаштувань та API.

### Ринковий proxy для Android

Налаштуйте й опублікуйте Apps Script за [інструкцією](apps-script/README.md), задайте FINO_PROXY_URL і FINO_PROXY_TOKEN у .env. Proxy-токен повинен збігатися з FINO_PROXY_TOKEN у Script Properties. Ключі ринкових провайдерів налаштовуються у Script Properties.

## Android

Незалежне перенесення без Google Drive: **Налаштування → Файл портфеля**. Явний JSON-експорт містить приватні незашифровані дані; створюється тільки після підтвердження. Перед відновленням перевіряються формат v1, SHA-256 і document validation та показується preview; відновлення можливе лише в порожній портфель. На чистому Android створюється локальний профіль без Google-авторизації. Формат, обмеження, безпечні кроки перенесення й recovery drill: [PORTFOLIO-FILES.md](PORTFOLIO-FILES.md). Новий native document picker потребує наступної окремо дозволеної збірки APK.

Перед перескладанням виконайте `npm.cmd test`, `npm.cmd run mobile:prepare` і `npm.cmd run mobile:check`. Prepare готує лише `.tmp/mobile-web/`, не змінюючи Android assets або APK. Preflight перевіряє синтаксис, HTML-посилання, SHA-256 frontend/shared ресурсів для Android, конфігурацію проксі та реєстрацію плагінів. Детальний результат перевірки й кроки на телефоні: [MOBILE-READINESS.md](MOBILE-READINESS.md).

На екранах до 700 px Fino використовує спільну нижню навігацію для Investment / Wallet із меню «Ще». Архітектура, вкладки, підтримка Android та перевірки: [MOBILE-NAVIGATION.md](MOBILE-NAVIGATION.md).

~~~powershell
npm run mobile:sync
npm run mobile:open
npm run mobile:build
~~~

mobile:sync генерує frontend/js/mobile-config.generated.js, готує `.tmp/mobile-web/` із frontend та shared і копіює ресурси через Capacitor. Copy hook оновлює підготовлені ресурси перед копіюванням. mobile:build повторює sync, потім збирає debug APK. Команда mobile:apk є її псевдонімом.

Окрема перевірка Android без створення APK: `android\gradlew.bat -p android :app:compileDebugJavaWithJavac :app:testDebugUnitTest :app:lintDebug` у середовищі з JDK 21 та Android SDK 36. Для Windows-шляхів із кирилицею Gradle використовує `file.encoding=COMPAT`; Java-файли компілюються явно як UTF-8.

Instrumentation-контракти — `android/app/src/androidTest/java/com/tandy03/fino/ExampleInstrumentedTest.java`: application ID `com.tandy03.fino`, реєстрація й методи FinoStorage/AppLock/GoogleDriveAuth та bundled plugins, локальний HTTPS WebView, наявність offline frontend/shared ресурсів, реальні set/get/remove із підтвердженням запису й перевідкриттям Activity, validation failure та типи налаштувань блокування. OAuth, PIN і фінансові ключі не змінюються; storage probe має унікальний `fino-instrumentation-*` ключ і finally-cleanup. Перевірка компіляції без APK: `android\gradlew.bat -p android :app:compileDebugAndroidTestJavaWithJavac`. Запуск `connectedDebugAndroidTest` збирає/встановлює APK, тому виконується лише за окремим дозволом на виділеному тестовому емуляторі; він не входить у source-only перевірку.

`npm run check:frontend` включає `check:state-mutations` для всіх UI-модулів; правила позиченого фінансового стану й межі статичного аналізу описані у [FRONTEND-STATE.md](FRONTEND-STATE.md). Панель відновлення команд використовує локалізацію всіх шести мов, зберігаючи початкові operationId/scope при повторі. Оновлення FX перемальовує видимий екран; приховані фінансові екрани оновлюються при відкритті.

APK: android/app/build/outputs/apk/debug/app-debug.apk.

Перевірений debug APK у `android/app/build/outputs/apk/debug/app-debug.apk` публікується в гілці `mobile-app` за явною вказівкою власника. APK містить видимий клієнту proxy-токен; приватні ключі провайдерів залишаються в Apps Script Properties. Інші APK, `.env`, OAuth-токени та ключі підпису ігноруються Git. Для власної збірки налаштуйте локальний `.env` і виконайте `mobile:apk`.

Якщо `.tmp/android-tools/user-home/debug.keystore` існує, debug-збірки явно використовують цей збережений ключ у CLI й Android Studio. Це зберігає підпис робочого застосунку та налаштування Android OAuth; не замінюйте ключ новим. Файл ключа і його резервна копія залишаються поза Git.

Android не запускає Node.js backend. frontend/js/api.js делегує операції mobile-api.js; дані зберігаються через Capacitor Preferences окремо для Google-акаунта та синхронізуються з Drive. Авторизація виконується власним GoogleDriveAuthPlugin; для іншого пакета або підпису застосунку потрібне відповідне налаштування Android OAuth client. PIN і біометрію реалізовано в MainActivity та AppLockPlugin.

Спільні реалізації розташовані в `shared/`: `frontend → shared`, `backend → shared`; зворотних залежностей немає. Web отримує локальні `/shared/…` ресурси від Express, Android — ті самі файли в пакеті. Перелік модулів, compatibility exports і правила пакування описані в [SHARED.md](SHARED.md).

Зміни лише в backend не потребують нового APK. Після змін frontend або shared необхідно за окремим дозволом виконати mobile:sync і перебудувати застосунок.

## Перевірки

`npm run lint` перевіряє **весь авторський `frontend/js` і `shared`** за каталогами, без ручного переліку модулів. Vendor і `*.generated.js` виключені; нові файли автоматично потрапляють у перевірку. `lintCoverage.test.js` звіряє фактичне охоплення з деревом файлів. Backend і Apps Script залишаються поза цим ESLint scope та перевіряються своїми тестами/source preflight. `npm run test:recovery` запускає синтетичний повний цикл збереження/відновлення; він також входить у звичайний `npm test` і CI, без доступу до реального портфеля чи Drive.

~~~powershell
npm test
~~~

Тести перевіряють нормалізацію даних провайдерів, історичну дохідність, FIFO, валютні курси, Crypto Earn, допоміжну логіку Drive та HTTP-сценарії портфеля, виплат, бюджету й паралельного запису. Окремі тести перевіряють мобільні конфлікти ревізій, незавантажені зміни, offline, резервні копії, погашення та відображення поточної вартості. Також перевіряються зміна акаунта посеред операції, пошкоджений JSON, повторне створення Drive-файлу після помилки, паралельні запити першого запуску та одночасне читання й запис мобільних даних. HTTP-тести використовують тимчасовий JSON і підмінений Drive, не змінюють особистий портфель.

Збірка Android, реальна Google-авторизація й робота зовнішніх API потребують окремої перевірки.

Для перевірки встановлених залежностей використовуйте `npm.cmd ls --all` і `npm.cmd audit` (у Windows PowerShell). Оновлення в межах сумісних версій: `npm.cmd update --save`, після цього — `npm.cmd test` і `npm.cmd run mobile:sync`.

У `package.json` зафіксовано вузькі `overrides` для `uuid` у `gaxios@6` та `xcode`: версія 11.1.1 виправляє [GHSA-w5hq-g745-h8pq](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq), зберігаючи CommonJS і потрібний цим пакетам виклик `v4()`. Регресійні тести перевіряють multipart-запит Google auth transport та генерацію Xcode ID. Перегляньте ці overrides, коли upstream-пакети оновлять власні залежності.

## Збереження даних і поточні обмеження

- Вебдані зберігаються в backend/data/data.json; записи виконуються через тимчасовий файл і перейменування. Перед ручним перенесенням даних зупиніть backend і збережіть копію JSON.
- Desktop backend призначений для особистого використання через localhost. Публічне розгортання потребує окремої автентифікації та перегляду моделі доступу.
- Backend, вебаналітика й Android використовують спільний `portfolio-rules.js`; HTTP і native адаптери перевіряються окремими регресійними тестами.
- Мобільна синхронізація зберігає останню спільну копію та стан незавантажених змін окремо для кожного Google-акаунта. Конфлікт не замінює жодну копію автоматично: виберіть Upload або Download; перед заміною створюється резервна копія. Backup створює окремий JSON у fino-backups. Помилки фонового завантаження й очікування відображаються у статусі. Новий Drive-файл створюється разом із JSON одним запитом; зміна акаунта посеред операції зупиняє її, зберігаючи локальні дані.
- Автоматичного об’єднання конфліктних змін немає. Після оновлення зі старої версії невідома історія синхронізації обробляється обережно: якщо копії відрізняються, потрібен ручний вибір. Умовний запис використовує ETag, коли Drive повертає його; перед перезаписом віддалена копія також резервується.
- POST /api/transactions і POST /api/payments перевіряють актив, тип, дату, суму й валюту; ID, час створення та назву активу формує backend. Дробова кількість дозволена для акцій, ETF і Crypto Earn. Нові виплати мають статус planned; отримання записується окремим endpoint.
- .env, OAuth credentials і refresh tokens не слід додавати до Git. Згенерований proxy-токен входить до APK і доступний серед вебресурсів; він не є надійним механізмом автентифікації окремого користувача.

## Надійність синхронізації та зберігання

Чіткі інваріанти, стани, результати операцій і межі захисту описані в [DATA-CONTRACT.md](DATA-CONTRACT.md). Стани: `local-saved`, `sync-pending`, `sync-confirmed`, `conflict`, `auth-required`. Успішний локальний запис не означає upload або backup: `savedLocally`, `savedRemotely`, `backupSaved` перевіряються окремо. Після upload Drive має підтвердити збережений JSON; backup не переводить незавантажені зміни в confirmed.

Backend веде журнал `backend/data/data.json.journal.ndjson` з контрольними сумами та записами prepare/commit/confirmed, відновлює останню завершену версію після пошкодження JSON і зберігає незавантажені зміни після рестарту. Не видаляйте журнал для усунення конфлікту: він містить фінансову історію й не входить до Git. Ручний Download створює копію локальної версії, зупиняє старі фонові uploads і перевіряє, чи не з’явилися нові локальні зміни.

Native журнал зберігає дані й sync-метадані одним записом для кожного акаунта; старі Preferences-ключі є сумісними копіями. Новий `FinoStoragePlugin` підтверджує запис на диск через SharedPreferences.commit(). Плагін окремо скомпільовано javac без збірки APK. Повна Android-збірка та перевірка на пристрої залишаються до погодження нового APK.

Сервер призначений для localhost. Browser API потребує HttpOnly SameSite=Strict сесії; forwarding-заголовки proxy та чужі origins відхиляються. Прямі локальні CLI-запити залишаються довіреними: публічний reverse proxy потребує окремої авторизації. Дані зовнішніх джерел валідовані до використання; запити мають бюджети, обмеження паралельності й тайм-аути. Логи допускають лише діагностичні поля, без записів портфеля та секретів.

Поточний npm audit: 0 відомих уразливостей (13.10.2026). Google API та jsdom мають нові major-версії; перевірені сумісні версії залишені. Vendor Chart.js 4.5.1 звірений з [офіційними релізами](https://github.com/chartjs/Chart.js/releases).

`.env`, OAuth, токени, журнали, keystore та API-нотатки ігноруються Git. Windows ACL для наявних секретних файлів ще не звужені: системний дозвіл на виконання підготовленого `backend/scripts/protectSecrets.ps1` відхилено. Нові token-файли записуються атомарно з приватними правами. В APK proxy-токен доступний для витягування; справжні ключі провайдерів мають залишатися в Apps Script Properties. Наявний APK уже відстежується Git — перед публікацією потрібен перегляд політики артефактів і токена.

Ці зміни не включають збірку APK, staging/commit/push у Git або публікацію Apps Script.

Помилки HTTP API мають єдиний контракт `{ error, code, category }`, HTTP-статус і заголовки `X-Request-Id` / `X-Error-Category`. Їх формує спільний middleware; маршрути лише передають помилки або додають безпечний контекст провайдера. Для sync-помилок сумісне поле `status` містить лише стан і булеві ознаки збереження. Desktop і native використовують спільну нормалізацію; повідомлення в інтерфейсі показують ID для діагностики. Детальний контракт описано в `DATA-CONTRACT.md`.

Методи, шляхи, вхідні поля, відповіді, помилки та межі request/domain/document validation описано в [API-CONTRACT.md](API-CONTRACT.md). Контрактні тести перевіряють HTTP і Android на однакових даних; правила нових операцій не застосовуються до старих snapshot під час імпорту або відновлення.
