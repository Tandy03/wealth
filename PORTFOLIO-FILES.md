# Незалежне перенесення портфеля

Google Drive, Apps Script і системний Android backup для цього сценарію не потрібні. У web потрібен запущений локальний backend; Android працює зі своїм локальним сховищем без мережі. На новій Android-інсталяції спочатку налаштуйте PIN; Google-авторизація для відновлення файлу не потрібна.

## Створення копії

1. Завершіть або відновіть невизначені команди в панелі відновлення. Експорт містить лише збережений портфель, не outbox і не незавершені запити. UI блокує експорт, якщо журнал команд пошкоджений або містить unfinished-команди.
2. Відкрийте **Налаштування → Файл портфеля → Експортувати файл портфеля**. Прочитайте попередження про приватні незашифровані дані та підтвердьте експорт. Саме відкриття налаштувань нічого не експортує.
3. У браузері перевірте завершення завантаження `fino-portfolio-YYYY-MM-DD.json`. Android відкриває системний вибір місця збереження; успіх показується після запису й закриття потоку документа. Скасування не повідомляє про збереження. Немає прихованого експорту чи автоматичного надсилання файлу в хмару.
4. Тримайте копію в надійному місці. До видалення старої інсталяції перевірте файл через попередній перегляд на порожній інсталяції; не покладайтеся лише на повідомлення про початок браузерного завантаження.

Файл містить приватну історію активів, операцій, продажів, виплат, цін, нотаток, Wallet, ребалансу та збережені квитанції operationId. Підтвердження Drive й `sync` пристрою не переносяться. Налаштування OAuth/акаунта, proxy-конфігурація, токени, PIN, біометрія, журнали пристрою, UI-кеш і outbox лежать поза фінансовим документом і не включаються в експорт. Файл не зашифрований; SHA-256 не замінює шифрування або перевірку походження файлу.

## Перевірка й відновлення

У native-конфігурації `loggingBehavior: none` вимикає стандартне логування аргументів Capacitor (воно може містити фінансовий JSON). Поки відкритий document picker, payload експорту тримається лише в обмеженому буфері пам'яті та не включається в saved-state Bundle Activity. Після запису/скасування буфер очищається. Якщо Activity/процес було знищено й payload втрачено, експорт завершується явною помилкою: повторіть його й перевірте файл, замість припускати успіх. Портфель при цьому не змінюється.

1. На порожній інсталяції відкрийте той самий розділ і натисніть **Вибрати файл портфеля**. Android використовує системний document picker; браузер — локальний file input. На цьому етапі фінансовий документ не записується.
2. Перевіряються розмір (до 1 MiB UTF-8), формат і версія, SHA-256, JSON та правила документа/legacy-міграції. Нові request-правила створення активів не застосовуються до історії. Показуються дата експорту, кількість основних записів і контрольна сума.
3. Лише **Відновити перевірений портфель** записує документ. Доменний сервіс повторно перевіряє файл, порожній стан і scope/checksum призначення всередині єдиної mutation queue. Наявні активи, виплати, Wallet, нотатки або плани не затираються. Об'єднання двох портфелів не виконується. Скасування, пошкоджений файл, помилка диска або застарілий preview не означають успіху.
4. Після успіху snapshot завантажується штатною store-командою. Повідомлення розрізняє **збереження локально** і **непідтверджене вивантаження на Drive**. Нові локальні journal/metadata створюються на пристрої; чужі baseline, revision та підтвердження upload не успадковуються.

Чиста Android-інсталяція без акаунта отримує профіль `local-only`. Перезапуск, фінансові операції й повторний експорт цього профілю не потребують Google. Автоматична синхронізація не відкриває OAuth і не надсилає його дані іншому акаунту. Перед перемиканням на Google через Reconnect збережіть файл: акаунти ізольовані, автоматичного перенесення локального профілю в Google-акаунт немає. На web/Android із уже обраним акаунтом файл можна відновити лише в його порожній портфель; якщо в Drive інші дані, штатна перевірка конфлікту не дозволяє непомітно їх перезаписати.

## Формат v1

JSON envelope має рівно `format: "fino-portfolio"`, `version: 1`, ISO `createdAt`, фінансовий `document` і hex `checksum`. Контрольна сума — SHA-256 UTF-8 від канонічного JSON усіх полів, крім `checksum`: ключі об'єктів відсортовані, порядок масивів збережений. Переноси й порядок ключів файлу не впливають на перевірку. Вкладений `document` має власну schema version і перевіряється `shared/state-model.js`; нормалізація при читанні може відновити legacy/derived поля.

Це окремий формат. Довільний `data.json`, файл OAuth, export із іншого застосунку чи raw Drive backup не слід подавати в UI замість нього. Модуль `shared/portfolio-transfer.js` використовується і backend, і браузером/Android без копіювання фінансових правил. Чинний старий APK ще не містить цього інтерфейсу та native document picker; вони з'являться після окремо дозволеної збірки.

## Регулярна перевірка відновлення

`npm run test:recovery` запускає `portfolioRecovery.test.js`; цей файл також автоматично входить у `npm test` та наявний CI для push/PR. Тести створюють лише синтетичні дані в окремих тимчасових каталогах/Map, без реальних файлів користувача, Google чи API-ключів.

Повний цикл створює актив, продаж і докупівлю через доменні команди, додає мультивалютний актив, отриманий дохід із пов'язаною транзакцією, Wallet та ребаланс; експортує файл, відновлює його в чисте сховище й після перезапуску звіряє checksum і кількість, собівартість, sale profit, received income, витрати, позики, плани та operationId. Перевіряються відсутній/обірваний JSON, незавершений запис journal, prepare без commit, необоротне пошкодження journal, втрата native mirrors/metadata, збій commit, повторна спроба, конкурентне відновлення та незалежне native-відновлення без авторизації. Пошкоджений journal зберігається; якщо відновити його неможливо, тест використовує окремий експорт у новому сховищі, не перезаписує пошкоджене джерело.

UI smoke перевіряє web/native всіма шістьма мовами: відсутність автоматичного експорту, попередження/скасування, перевірку без запису, підтвердження restore, read-only export та відмову від пошкодженого файлу/непорожнього призначення. Фізичний Android picker і конкретного storage provider перевіряють окремо на тестовому пристрої; ці JS-тести не доводять виконання Java-коду.
