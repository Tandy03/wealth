# Portfolio Share Card — реалізація та перевірка

Локальна реалізація від 21.10.2026. Кнопка **Share** розташована в Dashboard безпосередньо ліворуч від **Add asset**. Модальне вікно дозволяє вибрати період, показники, тему, переглянути картку та явно створити PNG. Картка не є резервною копією; для перенесення даних використовується [JSON-експорт](PORTFOLIO-FILES.md).

## Аудит та ізоляція

Fino використовує classic JavaScript/UMD без frontend framework або bundler; Android — Capacitor 8/WebView. Збережено існуючі фінансові сервіси, store, API, auth/sync, структуру документа та чотири теми. Нових npm-залежностей, endpoint-ів, фінансових правил або міграцій немає.

Код Share не записує фінансові дані. Контролер створюється лише після натискання, не виконує мережевих запитів і не є залежністю інших екранів. Якщо необов'язковий Share-модуль недоступний, Dashboard продовжує працювати.

## Джерела та методика

Використовуються `FinoMarketData`, `FinoPortfolioFinance`, `FinoCashflow`, `FinoValues` і чинна модель документа. Share формує read-only проєкцію результатів сервісів; кількість, собівартість, продажі, виплати, завершеність, dedup/mirror та XIRR не обчислюються новими доменними алгоритмами.

**Current** обирається заново при кожному відкритті. Метрики мають визначення Dashboard: записана оцінка відкритих позицій, собівартість залишку, реалізований результат, нереалізований результат, їхній загальний прибуток, чинна база Return та XIRR з `calculatePortfolioXirrDetails`. Часткову оцінку й приблизний XIRR позначено. Savings виключені. Кількість активів — кількість відкритих груп тип/назва, як у Dashboard, а не кількість лотів.

**All time** використовує накопичені показники; початок — перша доступна завершена покупка. **1M/3M/6M/1Y** віднімають календарні місяці з обмеженням до останнього дня місяця, **YTD** починається 1 січня. Дні узгоджені з локальними календарними днями `FinoValues.getDateString`. **Custom** відхиляє неможливі дати, початок після завершення та завершення в майбутньому.

Для інших періодів:

- Реалізований результат визначає чинний `calculateProfit(from, to)`, прив'язаний до дати завершення для FX. Це прибуток продажів та отриманий дохід, а не всі надходження або сума продажу. Використовуються фактична дата отримання, чинні completion/dedup правила й відокремлення основної суми погашення.
- Кількість і собівартість беруться зі спільних правил на дату завершення. Використовуються записані котирування не пізніше цієї дати. Початковий запис ціни покупки не видається за ринкове котирування. Без історичної оцінки — `Unavailable` або явно часткова оцінка; поточна ціна не переноситься в минуле.
- Чинна модель не надає узгоджених **Profit, Return та XIRR саме за довільний період**. Ці поля позначені недоступними з поясненням; накопичений прибуток або XIRR від першої покупки не видається за місячний результат. Користувач може вимкнути такі поля.
- Суми — у UAH, чинній валюті Dashboard. Для минулої дати використовується історичний FX-кеш через чинний `rateInfo`. Майбутній поточний курс не видається за підтверджений історичний. Missing/fallback/stale/undated дані позначаються; без потрібного FX точна сума недоступна.

XIRR у Current/All time залишається річною ставкою за датованими потоками. Необліковані податки/комісії не додаються. Розподіл використовує ті самі **класи активів**, що й Asset Allocation. Current зберігає його чинний fallback до ціни покупки з приміткою про якість; для минулої дати fallback до поточної ціни заборонений. Неповний розподіл явно позначено.

## Приватність, локалізація та теми

Суми за замовчуванням вимкнені. Увімкнені Return, кількість активів, Allocation та branding; кожен показник вимикається окремо. Приховані значення відсутні в SVG, accessible labels, назві PNG й тексті Web Share. Назви конкретних активів, рахунки та особисті дані в картку не потрапляють. Налаштування не зберігаються в базі або localStorage.

Картка читає наявні CSS design tokens Dark, Light, Monochromatic та Analog, не перемикаючи тему root документа. Дати, суми, відсотки й підписи локалізовані. Модальне вікно обмежує фокус, підтримує Escape, повертає попередній фокус і відновлює `inert` після закриття. На вузькому екрані preview показано над налаштуваннями; прокручування враховує safe areas.

Генерація локальна, публічних URL немає. Лише після явного системного Share користувач сам обирає одержувача.

## PNG та Web Share

SVG **1080 × 1080** — єдине джерело preview й PNG. Exporter після явного натискання чекає готовності потрібного SVG-шрифту через `document.fonts.load('16px Arial')`, декодує локальний SVG, малює один Canvas і викликає `toBlob('image/png')`. Очікування сторонніх webfonts інтерфейсу не блокує експорт. SVG не містить зовнішніх зображень, `foreignObject` або віддалених шрифтів; Arial/system fallback підтримує кирилицю. Canvas і тимчасовий SVG URL очищаються.

Download використовує Blob URL та `a[download]`. URL звільняється перед наступною дією або при закритті. Повідомлення каже «завантаження розпочато», не гарантує запис користувачем.

Share перевіряє файли через `navigator.canShare`. Перший клік готує PNG, другий **Open share menu** викликає `navigator.share({files})` до першого `await`, зберігаючи user activation. Без підтримки файлів — Download fallback. Cancellation не є критичною помилкою; інші збої дозволяють повтор. Реальне надсилання одержувачу не виконувалося.

Не більше одного export одночасно. Зміна налаштувань/акаунта чи закриття скасовує або відкидає старий результат; пізня відповідь не запускає download. PNG для другого кліку утримується лише до зміни налаштувань або закриття.

## Android: готовність і додаткові кроки перед релізом

Preview, дані, локалізації та локальні ресурси перевірені native UI harness і mobile preflight. Наявний `PortfolioTransfer` — JSON picker, він не підтримує PNG/Share Sheet. Android WebView не прирівнюється до браузера.

**У коді підготовлено `PortfolioSharePlugin` для PNG-збереження через SAF та поширення через окремий вузький FileProvider.** JS-адаптер автоматично перевіряє наявність плагіна, передає тільки готовий PNG і викликає native-дію одним натисканням. У старому APK без плагіна PNG-дії залишаються вимкненими з поясненням. Web Share API у WebView не використовується як fallback.

Контракт, межі пам'яті/кешу, скасування, життєвий цикл і список перевірок описані в [ANDROID-PNG-SHARE.md](ANDROID-PNG-SHARE.md). JSON `PortfolioTransfer`, обчислення картки, авторизація й синхронізація не змінені. Native-системні діалоги, app lock, поворот/відновлення Activity та RAM на телефоні потребують перевірки після окремого дозволу на Android-збірку; APK у цьому етапі не створювався.

## Продуктивність і результати перевірок

- Контролер, DOM, звіти й PNG створюються лише за явними діями. Завантажуються невеликі локальні визначення модулів, без важких бібліотек та відкладених runtime-імпортів, які можуть зламатися offline.
- Кеш обмежений 12 наборами параметрів на відкриту сесію, скидається після зміни даних/FX. Тема та прапорці не перераховують фінанси. Великі масиви не deep-clone-яться; historical view копіює лише об'єкти активів для датованих котирувань.
- Коли вікно закрите, немає share-обчислень, PNG, API-запитів або share subscription. UI-тести перевіряють нуль запитів і незмінність документа web/native. Продуктивність фізичного телефона не вимірювалася.
- `npm test`: **518 тестів пройшли**, включно з чинними фінансовими, API, UI, auth/sync та mobile-adapter регресіями. Перевірки включають виправлення довгих підписів і збереження порядку класів Allocation; після уточнення відступу SVG повторені export-перевірки.
- `npm run lint`, `npm run check:frontend`: успішно. Окремого TypeScript/typecheck чи bundler build у проєкті немає; перевіряються ESLint, синтаксис і реальні HTML/local scripts.
- Локальний Chrome на синтетичному портфелі: **24 валідні PNG 1080 × 1080** (6 мов × 4 теми); перевірені PNG signature, dimensions, непрозорість, кольори та межі SVG-тексту. Додатково дві stress-картки з усіма класами й великими сумами: Current і минулий Custom. **30 layout-перевірок**: 6 мов × 320/360/390/768/1500 px без переповнення модального вікна. Виправлений довгий німецький підпис на 320 px.
- Справжня кнопка Download PNG зберегла файл у Chrome. Його SHA-256 збігся з PNG із preview SVG. Приклади лише синтетичних даних — `.tmp/share-review/`.
- `npm run mobile:prepare`, `npm run mobile:check`: 98 локальних ресурсів, 82 посилання, 219 JavaScript sources, 15 shared modules. Це підготовка ресурсів без Capacitor sync або Android build, не перевірка фізичного WebView/Share Sheet.

Усі зміни локальні. Gradle, APK/AAB build, встановлення на телефон, app ID/signing changes, міграції, Git commit/push, PR і deploy не виконувалися. SHA-256 чинного APK не змінився: `29EEBDC9926920E4C54DBD90C3F0B98BDCA09D740F8F2C441A33E4EF646590FF`.
