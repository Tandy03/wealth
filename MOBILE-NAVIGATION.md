# Адаптивна нижня навігація Fino

## Поведінка

На екранах до 700 px включно одна фіксована нижня панель замінює старе горизонтальне меню. Це чинна мобільна межа Fino; від 701 px залишається попередня навігація. Перемикач Investment / Wallet та налаштування розташовані компактно вгорі. Підказку про горизонтальний свайп вилучено.

| Режим | Основна панель | Меню More / «Ще» |
| --- | --- | --- |
| Investment | Dashboard, Analytics, Market, Macroeconomics, More | Calendar, Portfolio, Transactions, Rebalance |
| Wallet | Current, Recorded expenses, Analytics, Loans, More | Archive |

Назви перекладаються чинною системою локалізації. Wallet використовує фактичні наявні сторінки; нових сторінок рахунків або категорій не створено. На мобільному перемикання режимів відновлює останню відкриту вкладку кожного режиму в поточному сеансі. На десктопі збережено початкову поведінку: Dashboard / Current; порядок інвестиційних розділів також починається з Dashboard → Analytics → Market → Macroeconomics → Calendar. Оформлення нижньої панелі й вкладки Wallet збережено.

## Архітектура

`createMobileNavigation` — один компонент із конфігураціями `navigationModes`. Він викликає наявні кнопки маршрутизації та спостерігає за активними розділами й видимістю оболонок. На десктопі кнопки не створюються, а спостереження відключене до переходу на мобільний розмір. Фінансовий store, API та формули компоненту не передаються. Реєстрація відбувається в composition root після чинних контролерів. Нових залежностей і нативних плагінів немає; іконки — локальні SVG.

Меню «Ще» — компактний немодальний Popover шириною 250 px, розташований над кнопкою More та вирівняний за її правим краєм. Він має заокруглення 16 px, рамку, тінь, трикутний вказівник і список пунктів від 48 px із роздільниками. Затемнення й великий заголовок прибрано. На низьких екранах список прокручується всередині меню.

Повторне натискання More, натискання поза меню, Escape або Back закриває Popover. Нижня панель залишається доступною; вибір основної вкладки теж спочатку закриває меню. Клавіші ↑/↓, Home та End переміщують фокус між пунктами, Tab виходить із меню. ARIA використовує menu/menuitem та aria-expanded; активний пункт підсвічується. Вибір пункту спочатку прибирає запис меню з history, а потім викликає чинну навігацію. Це зберігає історію сторінки активу. При переході до десктопного розміру меню закривається і повертає фокус на активну кнопку десктопного меню. Геометрія оновлюється при resize, зміні висоти панелі та visual viewport.

Панель враховує `env(safe-area-inset-bottom)` та бічні safe-area відступи. `ResizeObserver` узгоджує нижній відступ контенту з фактичною висотою панелі, зокрема при перенесенні довгих перекладів. Свайп-навігація призупинена, поки відкрите меню. Фінансові діалоги мають пріоритет над нижньою панеллю. Add asset та Share використовують чинні обробники.

Чотири теми використовують наявні CSS-токени. Для аналогової теми локальні суміші цих токенів забезпечують контраст підписів та іконок. Анімація відкриття Popover триває 180 мс і вимикається через `prefers-reduced-motion`.

## Перевірки

Основні команди:

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run check:frontend
npm.cmd run mobile:prepare
npm.cmd run mobile:check
node backend/scripts/mobileNavigationBrowserSmoke.cjs
```

`mobile:prepare` готує лише `.tmp/mobile-web`, без Capacitor sync та APK. Браузерний сценарій потребує готової production-збірки й локального Chrome; альтернативний шлях задається через `CHROME_PATH`. Він запускає ізольований сервер із синтетичними фінансовими даними та не звертається до реальних ринкових провайдерів. Звіти та знімки екрана зберігаються в `.tmp/mobile-navigation-browser-results.json` і `.tmp/mobile-nav-*.png`.

Матриця браузера: ширини 320, 360, 520, 700, 701, 768, 1440 px × чотири теми × шість мов × два режими, усього 336 комбінацій. Перевіряються відсутність горизонтального переповнення, приховування старого меню, правильний склад панелі, доступність останнього елемента контенту над нею, контраст підписів ≥ 4.5:1 та активної іконки ≥ 3:1. Для всіх 192 мобільних комбінацій додатково перевіряються ширина, вирівнювання та межі Popover, висота пунктів, прозорий фон і доступність кнопки More. Окремо перевіряються справжні натискання More та поза меню через CDP Input, Back, низькі viewport 180/240 px, повернення фокусу при resize та reduced motion. Знімки меню: `.tmp/mobile-more-dark.png`, `.tmp/mobile-more-light.png`.

Результати попередньої локальної перевірки 26.10.2026 (до перенесення Calendar у More; після цієї зміни тести, збірки та публікація не запускалися):

- Повний набір `backend/tests/*.test.js`: **554 / 554**, без пропусків і помилок, приблизно 113 с, зі стандартним лімітом пам'яті Node. Виконано після збірки frontend та UI-модулів тим самим Node test runner, що використовує `npm test`. Cleanup-hook звільняє DOM-посилання; переклади компонента перевіряються окремо від повного фінансового застосунку.
- `npm run lint` і `npm run check:frontend`: успішно; 81 локальний модуль, без циклів, відсутніх експортів і нових browser globals.
- `mobile:prepare` та `mobile:check`: успішно; перевірено 6 скомпільованих локальних ресурсів із 81 модуля, зокрема 15 спільних реалізацій. Android sync не запускався.

Реальні натискання More/поза меню, низькі екрани 180/240 px, reduced motion та повернення фокусу при resize працюють. Мінімальний контраст активного підпису 5.78:1, неактивного 4.50:1, активної іконки 3.14:1.

## Android та межі перевірки

Back використовує history WebView через наявний Capacitor App, без нового обробника нативного плагіна. Це узгоджено з чинною реалізацією AppPlugin: за відсутності JS-підписки на backButton він виконує WebView.goBack, якщо історія доступна. Web/native UI-тести перевіряють закриття меню через popstate та збереження фінансового стану.

Фізичний Android-пристрій і системні жести в цій задачі не перевірялися. Поточний Chrome не підтримує CDP-емуляцію safe-area inset; CSS-відступи реалізовано, але ненульовий системний inset потребує перевірки на пристрої. Відновлення останньої вкладки працює між режимами в одному сеансі; окремої персистентності маршруту після перезапуску не додано.

APK не перескладено, Android assets не синхронізовано. Коміти та push не виконувалися.
